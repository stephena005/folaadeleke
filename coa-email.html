SENDING IT THROUGH BEEHIIV ───────────────────────── beehiiv's Send API is Enterprise-only and in beta, so this goes through the ordinary post flow, one post per buyer: 1. The buyer has to exist as a subscriber to receive anything. If they are not one, add them AND tag them `coa-only`. 2. Segment: keep one MANUAL segment named "Certificate recipient". Before each send, replace its contents with this buyer's email (manual segments take a pasted address or a CSV). 3. New Post → + → Custom HTML → paste everything between the tags of the rendered file. 4. Audience → Email: "Certificate recipient". Audience → Web: REMOVE EVERY GROUP. 5. Send. Then empty the segment, so the next send cannot go out to the last buyer as well. THE WEB AUDIENCE IS THE ONE THAT MATTERS ──────────────────────────────────────── A beehiiv post publishes a web version by default, at a public URL, in the archive. This email carries the buyer's full name against their edition. Publish it and you have recreated exactly what anonymising the verify pages was meant to stop — except on a domain you do not control and cannot purge. Removing every group from the Web Audience is what makes the post email-only. CONSENT — worth being deliberate about ────────────────────────────────────── A certificate is transactional; a newsletter list is marketing. Adding a buyer to the audience to send them their certificate puts a customer into a marketing list they did not ask to join. The `coa-only` tag is the fix: exclude that segment from every marketing broadcast, so buyers who never subscribed only ever get the thing they bought. BEFORE SENDING — non-negotiable ─────────────────────────────── · The hero must already be deployed. Email clients have no site to be relative to; an undeployed image is a broken box in the inbox. Push first, then send. The renderer checks it with a live request and says so. · The verify page must be deployed, not just committed. The renderer checks that too, but check the page yourself: it carries this buyer's name, and sending the wrong link shows one buyer another buyer's certificate. · Send yourself a test first. Check desktop AND mobile. · Check the Web Audience is empty. Every time. It is the one mistake here that cannot be taken back.
